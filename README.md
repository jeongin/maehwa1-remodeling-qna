# 매화마을1단지 리모델링 Q&A

주민설명회 사전질의 수집용 정적 웹페이지. 서버 없이 GitHub Pages + Firebase(Auth/Firestore)로 동작합니다.

## 구조

```
index.html            화면 마크업
assets/styles.css     스타일
assets/core.js        Firebase 초기화 · 공용 상수/헬퍼
assets/auth.js        로그인 게이트 (동호수 + 휴대폰 뒷자리, 관리자 이메일)
assets/faq.js         자주 묻는 질문 탭
assets/board.js       질문 게시판 탭
assets/app.js         탭 전환 · 모달 · 부트스트랩
firestore.rules       Firestore 보안 규칙
```

## 로그인 방식

조합원은 **동 + 호수 + 비밀번호**로 입장합니다. 내부적으로는
`{동}-{호수}@resident.maehwa1.kr` 형태의 Firebase 계정을 쓰며, 실제로 메일이
오가지 않는 내부 전용 주소입니다.

Firebase 에 저장되는 비밀번호는 `PW_PREFIX + 사용자가 입력한 값` 입니다.
최초 입력값인 휴대폰 뒷 4자리가 Firebase 의 6자 최소 길이를 못 채우기 때문에
접두사로 보강합니다.

1. 첫 입장 — 동·호수, **휴대폰 뒷 4자리**, **조합 인증코드**를 입력하면 계정이 생성됩니다
2. 곧바로 **비밀번호 변경 창이 강제로** 뜹니다. 변경 전에는 닫을 수 없습니다
3. 이후부터는 동·호수와 **변경한 비밀번호**로 입장합니다
4. 헤더의 **🔑 비밀번호 변경** 버튼으로 언제든 다시 바꿀 수 있습니다

### 조합 인증코드

동·호수는 공개 정보라, 인증코드가 없으면 외부인이 임의의 세대를 선점할 수
있습니다. 그래서 최초 등록에만 조합이 배포하는 인증코드를 요구합니다.

코드는 `config/signup` 문서의 `code` 필드에 두고, 보안 규칙에서
`allow read, write: if false` 로 막습니다. **클라이언트는 이 값을 읽을 수
없고**, `users/{uid}` 생성 규칙이 대조할 때만 서버에서 사용됩니다. 공개된
JS 를 아무리 뜯어봐도 코드는 나오지 않습니다.

코드가 틀리면 명부 문서 생성이 거부되고, 직전에 만들어진 Auth 계정은
클라이언트가 곧바로 `deleteUser` 로 되돌립니다. 명부 문서가 없는 계정은
`verified()` 를 통과하지 못해 FAQ 열람도 질문 등록도 되지 않습니다.

코드를 바꾸려면 콘솔에서 `config/signup.code` 만 고치면 됩니다. 이미 등록한
조합원은 영향을 받지 않습니다.

강제 변경 여부는 `users/{uid}.pwChanged` 플래그로 판단합니다. 신규 등록은
4자리 숫자로만 가능하므로, 변경된 계정에 뒷자리를 넣어도 새로 만들어지지 않습니다.

강제 변경은 동·호수 계정이면 **관리자 권한이 있어도 적용**됩니다. 관리자 권한
계정이 휴대폰 뒷 4자리로 남아 있는 편이 더 위험하기 때문입니다.

관리자는 게이트 하단 **관리자 로그인** 링크에서 이메일/비밀번호로 들어갑니다.
이메일 계정은 강제 변경 대상이 아닙니다.

> **보안 수준에 대한 참고** — 최초 비밀번호인 휴대폰 뒷 4자리는 1만 가지뿐이라
> 약합니다. 그래서 첫 입장 시 변경을 강제합니다. 다만 이 강제는 화면 단에서
> 이루어지므로 개발자 도구로 우회할 수 있습니다. 우회해봐야 본인 계정만
> 약해지므로 실질적인 문제는 없지만, 금융·개인정보 수준의 보호가 필요한
> 용도에는 적합하지 않습니다. 민감정보는 게시판에 적지 않도록 안내하세요.

## Firebase 최초 설정

1. **Authentication → Sign-in method** — 이메일/비밀번호 사용 설정
2. **Authentication → Users** — 관리자 계정을 직접 추가
3. **Firestore → 데이터** — `config/admins` 문서 생성, `emails` 필드(배열)에 관리자 이메일 등록
4. **Firestore → 데이터** — `config/signup` 문서 생성, `code` 필드(문자열)에 조합 인증코드 등록
5. **Firestore → 규칙** — `firestore.rules` 내용을 붙여넣고 게시

색인은 따로 만들 필요가 없습니다. 조합원 조회는 `authorUid` 단일 조건이고,
관리자 조회는 `createdAt` 단일 정렬이라 자동 색인으로 처리됩니다.

## 데이터 모델

### 카테고리

FAQ와 게시판은 분류 체계가 다릅니다. `assets/core.js` 에 정의돼 있습니다.

- `FAQ_CATEGORIES` — 총회 / 주민설명회
- `BOARD_CATEGORIES` — 법무·세무·회계 / 설계 / 이주·이주비 / 총회 / 주민설명회 / 기타

게시판 카테고리를 바꿀 때는 `firestore.rules` 의 `create` 조건에 있는 목록도
함께 고쳐야 합니다. FAQ 카테고리는 규칙에서 검사하지 않습니다.

| 컬렉션 | 용도 | 읽기 권한 |
|---|---|---|
| `qa_items` | 자주 묻는 질문 | 로그인한 모든 조합원 |
| `questions` | 질문 게시판 | **작성자 본인 + 관리자만** |
| `users` | 동·호수 명부 | 본인 + 관리자 |
| `config/admins` | 관리자 이메일 목록 | 로그인한 모든 조합원 |

게시판의 비공개는 화면에서 가리는 방식이 아니라 `firestore.rules`가 강제합니다.
다른 사람의 질문은 브라우저 개발자 도구로도 읽을 수 없습니다.

## 커스텀 도메인 (maehwa1-remodeling.com)

저장소 루트의 `CNAME` 파일이 도메인을 지정합니다. 나머지는 Spaceship DNS와
Firebase 콘솔에서 한 번만 설정하면 됩니다.

### 1. Spaceship DNS 레코드

Spaceship → 해당 도메인 → DNS 레코드 화면에서 아래를 추가합니다.
파킹 페이지용 기본 레코드가 있으면 먼저 지웁니다.

| 종류 | 호스트 | 값 |
|---|---|---|
| A | @ | 185.199.108.153 |
| A | @ | 185.199.109.153 |
| A | @ | 185.199.110.153 |
| A | @ | 185.199.111.153 |
| CNAME | www | jeongin.github.io |

IPv6도 쓰려면 AAAA 레코드로 `2606:50c0:8000::153`, `2606:50c0:8001::153`,
`2606:50c0:8002::153`, `2606:50c0:8003::153` 를 `@` 에 추가합니다. 선택 사항입니다.

### 2. GitHub Pages

`CNAME` 파일이 푸시되면 **Settings → Pages** 의 커스텀 도메인이 자동으로 채워집니다.
DNS 검사가 통과하고 인증서가 발급된 뒤 **Enforce HTTPS** 를 켭니다.
발급까지 보통 몇 분에서 최대 24시간 걸립니다.

### 3. Firebase 승인된 도메인 (필수)

**Authentication → Settings → 승인된 도메인** 에 아래 둘을 추가합니다.

- `maehwa1-remodeling.com`
- `www.maehwa1-remodeling.com`

이 단계를 빠뜨리면 새 주소에서 로그인이 `auth/unauthorized-domain` 으로 실패합니다.

### 확인

```bash
dig +short maehwa1-remodeling.com
curl -sI https://maehwa1-remodeling.com | head -1
```
